# エレベータの ST プログラム かんたん解説

このプログラムは、**5階建てのエレベータ1台を動かす「頭脳」** です。
画面（TypeScript）のボタンが押されると、PLC がそれを受け取り、かごや扉をどう動かすかを決めます。

---

## 1. 全体のしくみ

```
 画面（ボタン・人数・重さ）
        │  Modbus で送る
        ▼
 ┌─ PRG_Elevator ─────────── 受付係：画面とのやり取りだけを担当
 │     │
 │     ▼
 │  FB_Elevator ─────────── 運転手：どこへ行くか、扉をどうするかを決める
 │     ├ FB_Door ─────────── 扉係：扉を少しずつ開け閉めする
 │     ├ FC_NextCallFloor ── 道案内：次に止まる階を探す
 │     └ FC_FloorBit ─────── 変換係：「3階」を「ランプの番号」に変える
 └──────────
        │  Modbus で返す
        ▼
 画面（かごの位置・扉・ランプ・警報）
```

**ポイント**
- 仕事を **係ごとに分けている** ので、どこに何が書いてあるか探しやすい
- 画面とやり取りするのは **受付係（PRG_Elevator）だけ**。運転手は画面のことを知らなくていい
- PLC はこの全体を **1秒間に約100回**（10ms ごと）くり返し実行している

---

## 2. ファイルの一覧

| ファイル | たとえると | 中身 |
|---|---|---|
| `GVL_ElevParam` | 仕様書 | 階数、定員、速さなどの決まりごと |
| `GVL_ElevIO` | 郵便受け | 画面と手紙をやり取りする箱 |
| `E_ElevState` | 状態の名前リスト | 「停止中」「移動中」などに番号をつけたもの |
| `E_Direction` | 方向の名前リスト | 停止・上・下 |
| `E_ElevCmd` | 指令の名前リスト | 行き先・呼ぶ・開・閉 |
| `PRG_Elevator` | 受付係 | 郵便受けを見て運転手に伝え、結果を郵便受けに入れる |
| `FB_Elevator` | 運転手 | エレベータの動きを決める中心 |
| `FB_Door` | 扉係 | 扉の開き具合を計算する |
| `FC_NextCallFloor` | 道案内 | 次に向かう階を探す |
| `FC_FloorBit` | 変換係 | 階の番号をランプの位置に変える |

> **名前の頭文字のルール**
> `PRG_` = プログラム、`FB_` = ファンクションブロック（記憶を持つ部品）、`FC_` = ファンクション（計算するだけの部品）、`E_` = 名前リスト（列挙型）、`GVL_` = みんなで使う変数の置き場

## 3. 決まりごと（GVL_ElevParam）

| 名前 | 値 | 意味 |
|---|---|---|
| `FLOOR_COUNT` | 5 | 階の数（1F〜5F） |
| `MAX_LOAD_KG` | 600 | 乗せられる重さ [kg] |
| `MAX_PERSONS` | 9 | 乗れる人数 |
| `SPEED_FLOORS_PER_S` | 0.5 | 速さ。1秒で半分の階を進む（1階分に2秒） |
| `DOOR_TRAVEL` | 2秒 | 扉が全部開くまでの時間 |
| `DOOR_DWELL` | 5秒 | 扉を開けておく時間 |

ここの数字を変えるだけで、**10階建てにしたり、定員を増やしたりできます**。画面も自動で合わせて変わります。

## 4. エレベータの「状態」（E_ElevState）

エレベータは、いつも次の6つのどれか1つの状態にいます。

| 番号 | 名前 | 意味 |
|---|---|---|
| 0 | Idle | 扉を閉めて止まっている |
| 1 | DoorOpening | 扉を開けている途中 |
| 2 | DoorOpen | 扉が開いている（乗り降りできる） |
| 3 | DoorClosing | 扉を閉めている途中 |
| 4 | Moving | 上か下へ移動中 |
| 5 | Overload | 重すぎる・人が多すぎる（警報） |

### 状態の移り変わり

```
 止まっている ──呼ばれた（別の階）──▶ 移動中 ──着いた──┐
     │                                                  ▼
     └──呼ばれた（この階）──────────────────▶ 扉が開く途中
                                                        │ 全部開いた
                                                        ▼
       ┌──── 重すぎる ◀──超えた──  扉が開いている  ──5秒たつ／閉ボタン──┐
       │                    ▲                                         ▼
       └──降りて軽くなった───┘                                  扉が閉まる途中
                                                                      │ 全部閉まった
                                                                      ▼
                                                                  止まっている
```

**大事なルール**
- **扉が閉まりきるまで動かない**（「移動中」になれるのは「止まっている」状態からだけ）
- **重すぎると扉が閉まらない**（「重すぎる」状態からは「扉が開いている」にしか戻れない）
- 扉が閉まりかけていても、開ボタン・その階の呼び・駆け込みで重すぎになったときは **開け直す**

このように「今の状態」と「何が起きたか」で次の状態を決める書き方を **ステートマシン（状態遷移）** といいます。ST では `CASE eState OF ... END_CASE` で書いています。

## 5. 各部品のしくみ

### 5-1. 受付係：PRG_Elevator

毎回（10ms ごと）、次の順で仕事をします。

1. **前回から何秒たったかを計る**
   - かごや扉を「時間 × 速さ」で少しずつ動かすのに使う
   - 時間が飛びすぎたときは 0.1 秒までにおさえる（止めたあとの再開でかごがワープしないように）
2. **郵便受けから指令を読む**
   - 指令の種類（1〜4）を名前リストに変える。知らない番号は「何もしない」にする
3. **新しい指令かどうか確かめる**
   - 画面は指令といっしょに **通し番号** を送ってくる
   - 番号が前回と違うときだけ「新しい指令」として扱う
   - だから **同じボタンを2回押しても、ちゃんと2回分として届く**
4. **運転手（FB_Elevator）を呼ぶ**
5. **結果を郵便受けに入れる**（状態、位置、扉の開き具合、ランプ、警報など）
   - 位置は小数（例：2.35階）なので、**100倍して整数（235）にして送る**。Modbus は整数しか送れないため
   - **ハートビート**：毎回1ずつ増える数字。画面はこれが増えているかで「PLC が生きているか」を確かめる

### 5-2. 運転手：FB_Elevator

いちばん大事な部品です。毎回、次の順で考えます。

1. **ボタンを受け付ける**
   - 押された階のランプを点ける
2. **重すぎないか調べる**
   - 重さが 600kg を超える、**または** 人数が 9人を超えると「重すぎ」
3. **状態に合わせて次の行動を決める**（4章の図のとおり）
4. **かごを動かす**（移動中のとき）
   - 1回で進む量 ＝ 速さ × 経過時間
   - 目的の階を **行き過ぎそうになったら、ぴったり階に合わせて止める**
5. **扉係に「開けて」か「閉めて」を伝える**
6. **着いた階のランプを消す**

### 5-3. 道案内：FC_NextCallFloor

「次にどの階へ行くか」を決めます。ルールは本物のエレベータと同じです。

> **今の方向の呼びを全部片付けてから、向きを変える**

例：かごが 2F にいて上に向かっている。4F と 1F で呼ばれた場合

1. 上方向に呼びがある → **4F へ行く**
2. 上方向に呼びがなくなった → 向きを変える
3. **1F へ行く**

上に向かう途中で 3F が呼ばれたら、通り道なので **3F にも止まります**。
これを全部ばらばらに対応すると、かごが行ったり来たりして、みんなの待ち時間が長くなってしまいます。

### 5-4. 扉係：FB_Door

扉の開き具合を **0%（閉）〜 100%（全開）** で計算します。

- 「開けて」と言われている間は少しずつ増やし、「閉めて」の間は少しずつ減らす
- 2秒で 0% → 100% になる速さ
- 100% で「全開」、0% で「全閉」を知らせる

本物のエレベータなら、ここはモーターへの指令と、扉の端にあるスイッチ（リミットスイッチ）になります。

### 5-5. 変換係：FC_FloorBit

「何階のランプが点いているか」を、**1つの数字のビット（0 と 1 の並び）** で表します。

| 階 | ビット | 数字 |
|---|---|---|
| 1F | `00001` | 1 |
| 2F | `00010` | 2 |
| 3F | `00100` | 4 |
| 4F | `01000` | 8 |
| 5F | `10000` | 16 |

例：2F と 5F のランプが点いていたら `10010` ＝ 18。
1つの数字で全部の階のランプを表せるので、送るデータが少なくてすみます。
存在しない階（0階や6階）が来たときは 0 を返し、**ないはずの階へ行かない** ようにしています。

## 6. 画面とのやり取り（郵便受けの中身）

**画面 → PLC（Holding Registers）**

| 番号 | 中身 |
|---|---|
| 0 | 指令の種類（1:行き先 2:呼ぶ 3:開 4:閉） |
| 1 | 何階か |
| 2 | 通し番号 |
| 3 | 人数 |
| 4 | 重さ [kg] |

**PLC → 画面（Input Registers）**

| 番号 | 中身 |
|---|---|
| 0 | 状態（4章の番号） |
| 1 | かごの位置 ×100 |
| 2 | いちばん近い階 |
| 3 | 方向（0:停止 1:上 2:下） |
| 4 | 扉の開き具合 [%] |
| 5 | 行き先ボタンのランプ（ビット） |
| 6 | 呼びボタンのランプ（ビット） |
| 7, 8 | 受け取った人数・重さ |
| 9 | いろいろな印（重すぎ・警報・全開・全閉・移動中） |
| 10 | 受け付けた通し番号 |
| 11〜13 | 定員の重さ・人数、階の数 |
| 14 | ハートビート |

## 7. 安全のための工夫

| 工夫 | どこで | なぜ |
|---|---|---|
| 扉が閉まってから動く | FB_Elevator | 扉が開いたまま動くと危ない |
| 重すぎると扉を閉めない | FB_Elevator | 重すぎるまま動かさない |
| 閉まりかけでも開け直す | FB_Elevator | 駆け込みや後から呼ばれたときに対応 |
| ないはずの階は無視 | FC_FloorBit | 画面から変な数字が来ても困らない |
| 知らない指令は無視 | PRG_Elevator | 同上 |
| 起動前に残っていた指令は実行しない | PRG_Elevator | 電源を入れた瞬間に勝手に動かない |
| 時間が飛んでもかごがワープしない | PRG_Elevator | 一時停止から再開したとき用 |
| 状態がおかしくなったら「止まっている」に戻す | FB_Elevator | 万一のための安全側への処理 |

## 8. 試しに変えてみよう

| やりたいこと | 変える場所 |
|---|---|
| 10階建てにする | `GVL_ElevParam.FLOOR_COUNT` を 10 に（16 まで） |
| 定員を増やす | `MAX_LOAD_KG` と `MAX_PERSONS` |
| もっと速くする | `SPEED_FLOORS_PER_S` を 1.0 に |
| 扉を長く開けておく | `DOOR_DWELL` を `T#10S` に |

> 動きそのもの（FB_Elevator など）を変えたときは、疑似PLC 用の `web/src/logic.ts` も同じように直し、`web` フォルダで `npm test` を実行してテストしてください。
